01
Sistema ✓ concluído
apt upgrade · timezone · utilitários base

Atualização do sistema operacional, ajuste de timezone e instalação dos utilitários que serão usados nas etapas seguintes.

# Atualizar pacotes do sistema
apt update && apt upgrade -y
# Instalar utilitários essenciais
apt install -y curl wget git unzip \
  ca-certificates gnupg lsb-release \
  ufw fail2ban
  • curl / wgetBaixar arquivos e scripts externos (instalador do Docker, por exemplo)
  • ca-certificatesValidar certificados SSL ao adicionar repositórios externos
  • gnupgVerificar assinatura GPG do repositório do Docker
  • lsb-releaseIdentificar a versão do Ubuntu (o instalador do Docker precisa disso)
  • ufwFirewall — configurado na Etapa 4
  • fail2banBloqueia IPs com tentativas repetidas de força bruta no SSH
# Ajustar timezone
timedatectl set-timezone America/Sao_Paulo && timedatectl
Time zone: America/Sao_Paulo (-03, -0300)
System clock synchronized: yes
NTP service: active
! O sistema pode avisar Pending kernel upgrade após o upgrade. Nesse caso, rode reboot e reconecte antes de continuar. Confirme com uname -r — deve mostrar a versão nova.
02
Docker Engine ✓ concluído
Docker CE 29.3.0 · Compose v5.1.1 · Buildx

Instalação do Docker Engine a partir do repositório oficial. Não usar o pacote do Ubuntu — a versão oficial do Docker é sempre mais atual e recebe patches de segurança mais rápido.

# Adicionar repositório oficial do Docker
install -m 0755 -d /etc/apt/keyrings

curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc

chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] \
https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" \
  | tee /etc/apt/sources.list.d/docker.list > /dev/null

apt update
# Instalar Docker e plugins
apt install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin
  • docker-ceDocker Engine — o runtime de containers em si
  • docker-ce-cliComando docker no terminal
  • containerd.ioRuntime de baixo nível usado pelo Docker internamente
  • docker-buildx-pluginBuilder multi-stage e multi-plataforma — necessário para nosso Dockerfile
  • docker-compose-pluginAdiciona docker compose (v2, sem hífen)
# Verificar instalação
docker --version && docker compose version && docker run --rm hello-world
Docker version 29.3.0, build 5927d80
Docker Compose version v5.1.1
Hello from Docker!
03
Usuário deploy ✓ concluído
uid=1002 · grupo docker · estrutura SSH

O usuário deploy é a identidade que o GitHub Actions vai usar via SSH para executar deployments. Nunca usar root para isso — em caso de comprometimento da chave, o dano fica limitado ao que o deploy pode fazer.

# Criar usuário e adicionar ao grupo docker
useradd -m -s /bin/bash deploy
usermod -aG docker deploy
# Configurar estrutura SSH
mkdir -p /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
touch /home/deploy/.ssh/authorized_keys
chmod 600 /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
  • chmod 700 .sshO SSH recusa conexão se a pasta tiver permissão mais aberta que 700
  • chmod 600 authorized_keysMesmo motivo — arquivo de chaves deve ser legível só pelo dono
$ id deploy
uid=1002(deploy) gid=1002(deploy) groups=1002(deploy),988(docker)
i A chave SSH pública do GitHub Actions deve ser adicionada em /home/deploy/.ssh/authorized_keys antes de configurar o workflow de CD.
04
Firewall UFW ✓ concluído
deny incoming por padrão · 4 regras ativas
# Configurar e ativar firewall
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP
ufw allow 443/tcp   # HTTPS
ufw allow 51820/udp # WireGuard (VPN com VPS DB)
ufw --force enable
! Sempre libere a porta 22 antes de ativar o UFW. Se ativar com a porta 22 bloqueada, perde o acesso SSH ao servidor.
$ ufw status verbose
To                         Action      From
22/tcp                      ALLOW IN    Anywhere
80/tcp                      ALLOW IN    Anywhere
443/tcp                     ALLOW IN    Anywhere
51820/udp                   ALLOW IN    Anywhere
05
Redes Docker ✓ concluído
ioc_frontend · ioc_backend (internal)

Duas redes isoladas. A rede backend tem a flag --internal — containers nela não conseguem acessar a internet diretamente, apenas se comunicar entre si.

# Criar redes e estrutura de diretórios
# Diretórios
mkdir -p /opt/ioc-portal/{app,storage/private,storage/public}
mkdir -p /var/log/ioc-portal/nginx
mkdir -p /etc/ioc-portal/nginx

# Rede frontend — Nginx ↔ PHP-FPM
docker network create \
  --driver bridge \
  --subnet 172.20.0.0/24 \
  ioc_frontend

# Rede backend — PHP-FPM ↔ Worker ↔ Scheduler (sem internet)
docker network create \
  --driver bridge \
  --subnet 172.20.1.0/24 \
  --internal \
  ioc_backend
  • --internalBloqueia saída para internet. Worker e Scheduler não precisam de acesso externo direto
  • --subnetRange de IPs internos. 172.20.0.x = frontend, 172.20.1.x = backend
06
Nginx + PHP-FPM ✓ concluído
Comunicação via FastCGI na rede ioc_frontend
# Subir containers
# PHP-FPM
docker run -d \
  --name ioc_app \
  --network ioc_frontend \
  -v /opt/ioc-portal/app/public:/var/www/html/public \
  --restart unless-stopped \
  php:8.2-fpm-alpine

# Nginx
docker run -d \
  --name ioc_nginx \
  --network ioc_frontend \
  -p 80:80 \
  -v /etc/ioc-portal/nginx/default.conf:/etc/nginx/conf.d/default.conf \
  -v /opt/ioc-portal/app/public:/var/www/html/public \
  -v /var/log/ioc-portal/nginx:/var/log/nginx \
  --restart unless-stopped \
  nginx:1.27-alpine
# Smoke test
docker ps && curl http://localhost
